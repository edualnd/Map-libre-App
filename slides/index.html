01

O que é o MapLibre?

Uma família de bibliotecas open source para desenhar mapas interativos — no navegador e em apps nativos.

Transição para a parte conceitual.
Motivação

Por que não usar só o Google Maps?

💳

Custo por uso

Serviços comerciais cobram por carregamento de mapa ou por requisição de tiles depois de uma cota gratuita.

🔑

Chave e conta

Exigem API key, cartão cadastrado e regras de uso que podem mudar a qualquer momento.

🔒

Aprisionamento

Estilo, dados e SDK amarrados a um fornecedor. Trocar depois significa reescrever o app.

✅ MapLibre: o motor de renderização é livre (licença BSD). Você escolhe de onde vêm os dados — servidor próprio, provedor pago ou projetos gratuitos como OpenFreeMap e OpenStreetMap.
Não é que Google/Mapbox sejam ruins — mas para projetos acadêmicos, ONGs e startups, custo e dependência importam. MapLibre separa o "motor" (renderização) da "gasolina" (dados).
História

Nasceu de um fork em 2020

📦Mapbox GL JS v1Biblioteca open source (BSD), muito popular na web
→
⚖️Dez/2020A v2 passa a ter licença proprietária e exige conta Mapbox
→
🍴Fork da v1.13A comunidade cria o MapLibre para manter o código livre
→
🚀HojeProjeto independente, com governança aberta e patrocínio de várias empresas
  • O mesmo aconteceu com o Mapbox GL Native → MapLibre Native (Android, iOS, desktop).
  • Desde então evoluiu muito: globo 3D, terreno, renderizadores Metal e Vulkan.
  • Licença BSD-3: uso comercial liberado, sem royalties.
  • Usa a MapLibre Style Spec: o mesmo JSON de estilo funciona em todas as plataformas.
Ponto-chave: por ser um fork, quem conhece Mapbox reconhece quase toda a API. O "mesmo JSON de estilo em todas as plataformas" é o que permite nosso app compartilhar a lista de mapas entre web e celular.

Destaque os três que usamos: GL JS (web), Native (embaixo do RN) e o wrapper React Native. Martin é mencionado para quem quiser servir seus próprios dados.

Como um mapa digital funciona

Tiles, fontes de dados, camadas e o Style JSON — os quatro conceitos que explicam tudo o que vem depois.

Parte conceitual — sem isso as demos parecem mágica.
Conceito 1

O mundo é dividido em tiles (ladrilhos)

z = 0

z = 1

z = 2

…
4z
z = 18
68 bilhões
  • A cada nível de zoom, cada tile se divide em 4.
  • O app só baixa os tiles visíveis na tela — por isso o mapa carrega rápido.
  • Endereço padrão: …/{z}/{x}/{y}.png
https://tile.opentopomap.org/14/6058/9295.png
                             │  │    └─ linha (y)
                             │  └─ coluna (x)
                             └─ zoom (z)
Ao vivo: map.showTileBoundaries = true · dê zoom
4^18 ≈ 68,7 bilhões de tiles: ninguém baixa tudo, só a janela visível. No mapa à direita, as linhas vermelhas são os limites reais dos tiles — dê zoom e veja cada quadrado se dividir em 4. O template {z}/{x}/{y} aparece em todos os estilos raster que veremos.
Conceito 2

Raster × Vetorial

🖼️ Raster📐 Vetorial
O que chegaImagem pronta (PNG / JPG)Geometrias + atributos (formato MVT / PBF)
Quem desenhaO servidorO seu aparelho (GPU), em tempo real
Mudar cores❌ Impossível✅ Basta trocar o estilo
Girar / inclinarTexto gira junto e fica ilegívelRótulos sempre de pé, prédios em 3D
Clicar e consultar❌ Só pixels✅ queryRenderedFeatures devolve nome, tipo…
Exemplos hojeSatélite, Topográfico, Ciclismo, NáuticoRuas e Lojas, Minimalista, Noturno, Prédios 3D
O MapLibre é especialista em vetorial, mas também exibe raster — é assim que conseguimos usar fontes como satélite e mapas temáticos.
Vetorial é o grande diferencial dos motores modernos. Raster continua útil para imagens (satélite) e para mapas temáticos prontos de projetos da comunidade.
Conceito 3

O Style JSON: a receita do mapa

📦 sourcesDe onde vêm os dados: vector, raster, raster-dem, geojson, image
🎨 layersComo desenhar, em ordem (a primeira fica embaixo): fill, line, symbol, circle, fill-extrusion, raster, hillshade, heatmap, background
🔤 glyphs · 🖼️ spriteFontes para os textos e a folha de ícones (lojas, ônibus, hospitais…)

Um estilo como o Liberty tem 111 camadas. Trocar o estilo = trocar a aparência inteira, sem mudar uma linha da lógica do app.

symbol — nomes de ruas e ícones de lojas
fill-extrusion — prédios 3D
line — ruas e avenidas
fill — água e parques
background — cor de fundo

Conceito 4

Expressões: estilo guiado pelos dados

  • ["get", "campo"] lê um atributo da feature.
  • ["match", …] escolhe um valor por categoria.
  • ["interpolate", …] varia suavemente com o zoom ou um número.
  • filter decide quais features entram na camada.
As expressões são avaliadas na GPU para cada feature, a cada quadro — funcionam igual na web e no celular.
// Cor do círculo conforme a categoria do ponto
"circle-color": [
  "match", ["get", "tipo"],
  "museu",  "#7c3aed",
  "parque", "#16a34a",
  "#e11d48"            // valor padrão
],

// Largura da rua cresce com o zoom
"line-width": [
  "interpolate", ["linear"], ["zoom"],
  10, 0.5,             // no zoom 10 → 0,5 px
  18, 14               // no zoom 18 → 14 px
],

// Mostrar só os POIs de comércio
"filter": ["==", ["get", "class"], "shop"]
Vamos usar exatamente o "match" por tipo na demo de GeoJSON mais à frente.

03

Web × App e instalação

Mesmo motor de estilos, duas formas de usar: imperativa no navegador e declarativa no React Native.

Agora a parte prática.
Comparativo

Web × App: o que muda?

🌐 Web — MapLibre GL JS📱 App — MapLibre React Native
Pacotemaplibre-gl@maplibre/maplibre-react-native → MapLibre Native (C++)
RenderizaçãoWebGL 2 no navegadorOpenGL ES ou Vulkan (Android) · Metal (iOS)
Estilo de APIImperativa: new Map(), map.addLayer(), map.on()Declarativa: <Map>, <Camera>, <Layer>
Instalaçãonpm ou uma tag <script> da CDNCódigo nativo → precisa de development build; não roda no Expo Go
Localizaçãonavigator.geolocation + GeolocateControl (exige HTTPS)GPS nativo: expo-location + <UserLocation>
RedeSujeito a CORS — o servidor de tiles precisa permitirSem CORS — qualquer servidor HTTP funciona
DistribuiçãoUma URL — atualiza na horaAPK / AAB / IPA via EAS e lojas
Os dois pontos que mais pegam na prática: (1) o Expo Go não serve, precisa de dev build; (2) CORS na web — vamos ver isso acontecendo na demo de Transporte.
Lado a lado

O mesmo mapa nas duas APIs

📱 App — declarativoApp.tsx
import { Map, Camera, UserLocation }
  from "@maplibre/maplibre-react-native";

export default function App() {
  return (
    <Map
      style={{ flex: 1 }}
      mapStyle="https://tiles.openfreemap.org/styles/liberty"
    >
      <Camera initialViewState={{
        center: [-46.63, -23.55],  // [lng, lat]
        zoom: 14,
      }} />
      <UserLocation />
    </Map>
  );
}
🌐 Web — imperativoApp.web.tsx
import * as maplibregl from "maplibre-gl";
import "maplibre-gl/dist/maplibre-gl.css";

const map = new maplibregl.Map({
  container: "map",            // <div id="map">
  style: "https://tiles.openfreemap.org/styles/liberty",
  center: [-46.63, -23.55],    // [lng, lat]
  zoom: 14,
});

map.addControl(new maplibregl.GeolocateControl({
  trackUserLocation: true,     // ponto azul
}));
Nos dois casos as coordenadas são [longitude, latitude] — a ordem do GeoJSON. Inverter é o erro nº 1 (o mapa vai parar no oceano).
Mesmos parâmetros, filosofias diferentes. No app, o estado do React controla o mapa; na web, você manda comandos para um objeto.

Instalação · App (Expo)

No app: Expo + config plugin

Terminal
# 1. Criar o projeto (TypeScript)
npx create-expo-app@latest meu-mapa \
  --template blank-typescript
cd meu-mapa

# 2. Instalar com versões compatíveis com o SDK
npx expo install @maplibre/maplibre-react-native \
  expo-location expo-dev-client

# 3. Gerar e instalar o app de desenvolvimento
npx eas-cli@latest build -p android \
  --profile development

# 4. Rodar o servidor e abrir no celular
npx expo start
app.json
{
  "expo": {
    "android": {
      "package": "com.duda.maplibreapp",
      "permissions": [
        "android.permission.ACCESS_FINE_LOCATION",
        "android.permission.ACCESS_COARSE_LOCATION"
      ]
    },
    "plugins": [
      "@maplibre/maplibre-react-native",
      ["expo-location", {
        "locationWhenInUsePermission":
          "Usamos sua localização para centralizar o mapa."
      }]
    ]

}
🚫 Expo Go não funciona: o MapLibre traz código nativo. Use o development build (passo 3) ou gere o APK. A v11 exige a Nova Arquitetura do React Native (padrão no Expo SDK 52+).
O config plugin injeta a configuração nativa (Gradle, Podfile) durante o build — você nunca edita as pastas android/ios à mão. O npx expo install resolve versões compatíveis com o SDK.
Permissões

Localização do usuário

  • App: declarar no app.json e pedir em tempo de execução. Sem o pedido, o mapa abre no lugar errado.
  • Web: o GeolocateControl chama navigator.geolocation e desenha o ponto azul.
  • Sempre tenha um fallback (ex.: centro de São Paulo) se o usuário negar.
No nosso app: getLastKnownPositionAsync() primeiro (instantâneo) e depois getCurrentPositionAsync() (preciso).

<Camera>

A câmera: para onde o mapa olha

📍 center

[lng, lat] do centro da tela

🔍 zoom

0 (planeta) até ~22 (sala de estar)

📐 pitch

Inclinação: 0° = de cima, 60° = perspectiva

🧭 bearing

Rotação em graus: 0 = norte para cima

  • initialViewState: posição inicial, sem "prender" a câmera.
  • trackUserLocation: "default", "heading" ou "course" — segue o usuário.
  • minZoom, maxZoom, maxBounds: limites.
flyTo faz o efeito "avião": afasta, viaja e aproxima. easeTo é uma transição direta. Vamos ver os dois em ação na demo de câmera.

export type MapMode = {
  id: string;
  label: string;
  icon: string;
  description: string;
  mapStyle: string | StyleSpecification;
  pitch?: number;   // ex.: 60 nos Prédios 3D
  zoom?: number;
  dark?: boolean;
  // Alternativa só para a web (ex.: servidor sem CORS)
  web?: { mapStyle: string | StyleSpecification;

// O Metro escolhe o arquivo pela plataforma:
//   App.tsx      → Android / iOS
//   App.web.tsx  → navegador
A extensão .web.tsx é resolvida automaticamente pelo Metro. Assim cada plataforma usa a biblioteca certa sem if/else espalhado pelo código.
Build e distribuição

Gerando o APK na nuvem com EAS

Terminal
# Login na conta gratuita do expo.dev
npx eas-cli@latest login

# Só na primeira vez
npx eas-cli@latest build:configure

# 📱 APK para instalar direto no Android
npx eas-cli@latest build -p android --profile preview

# 🍎 iOS no simulador (ou --profile preview
#    com conta Apple Developer)
npx eas-cli@latest build -p ios --profile ios-simulator

# 🌐 Versão web estática (pasta dist/)
npx expo export -p web
eas.json
{
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "android": { "buildType": "apk" }
    },
    "preview": {
      "distribution": "internal",
      "android": { "buildType": "apk" }
    },
    "ios-simulator": {
      "extends": "preview",
      "ios": { "simulator": true }
    }
  }
}
Ao terminar (~10–20 min), o EAS mostra um link e um QR code: abra no celular, baixe o .apk e instale. Não precisa de Android Studio.
Use npx eas-cli@latest em vez de npm install -g para evitar o erro EACCES em Linux. O perfil production gera .aab para a Play Store.
Lições aprendidas

Armadilhas que encontramos

📵

Expo Go

O app fecha ou não mostra o mapa. MapLibre tem código nativo → use development build ou APK.

🧱

Nova Arquitetura

MapLibre RN v11 exige a New Architecture. Use Expo SDK 52 ou mais novo.

⚙️

Worker da GL JS v6

"Worker failed to load" no Metro. Solução: servir o worker por public/ e chamar setWorkerUrl().

🚧

CORS na web

Servidor sem Access-Control-Allow-Origin → tiles bloqueados. No app funciona. Solução: fallback por plataforma.

🔐

EACCES no npm -g

Instalar global exige root no Linux. Use npx eas-cli@latest ou mude o prefixo do npm.

↔️

[lng, lat]

A ordem é longitude, latitude. Invertido, o mapa abre no meio do oceano.

Todas essas aconteceram de verdade durante o desenvolvimento deste app — vale contar a história de cada uma.
